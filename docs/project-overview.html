它是什么

收集 · 理解 · 交付，一条本地流水线

面向每月要手工收集多张发票的个人、自由职业者和小团队。把「翻邮箱、点下载、改文件名、做汇总」四件事压缩成一条可重跑、可复核的流程。

01

收集：邮箱与文件夹

IMAP 只读读取 QQ / 163 / 88 邮箱，或扫描手机导出、微信/支付宝下载、拍照发票所在的任意文件夹。附件、ZIP、链接都进入同一条流水线。

02

理解：本地识别

文本层 PDF、OFD、数电票 XML 直接解析；扫描件与图片交给本地 OCR；再按锚点规则抽取日期、金额、销方、票号等字段并做勾稽校验。

03

交付：分类与报表

按费用规则分类、标准化命名、自动撮合凭证，输出分类目录与 Excel 明细；无法可靠确认的材料进入「待人工复核」。

  • 本地优先：不调用模型服务，不需要 API Key；OCR 模型随依赖提供。
  • 不假成功：低置信度、无法勾稽、未命中规则的材料不会被硬归类。
  • 可重跑：文档指纹、发票业务键与布局迁移共同保证重复整理幂等。

为什么需要它

七个高频痛点，对应七种机制

项目不是「批量下载器」，而是把收集、识别、归类、核对和报表串成一条能解释结果的链路。

📧

发票散落几百封邮件

四层筛选先判断邮件像不像发票，再按日期范围批量拉取，避免整箱全量识别。

🔗

邮件只有下载链接

三级恢复：百望云自动化、税务平台直连、网页转 PDF，下载后与邮件里的期望字段比对。

🖨️

扫描件没有文字层

本地 OCR 在 200 DPI 下识别前两页，模型随安装包提供，不上传。

🏷️

文件名乱、分类靠手工

规则引擎按票种、关键词、金额范围决定目录，并生成标准文件名。

🧾

发票与水单/行程单对不上

撮合引擎按金额、日期、平台做最优匹配，配对件并排命名。

📊

报销汇总要手工复制

Excel 明细输出分类汇总、成功明细与异常记录三个工作表。

🔒

担心发票被上传云端

本地处理：凭据用 DPAPI / Keychain 加密，识别与归档不离开本机。

使用方式

三种模式，提取与整理可以分开用

桌面端「启动配置」页可切换任务模式。三种模式共享同一套识别、规则、归档与报表代码，区别只在入口和交接边界。

常规用法：连接邮箱，一次完成提取与整理

  • 01连接邮箱
  • 02拉取附件
  • 03恢复链接
  • 04本地识别
  • 05规则归类
  • 06归档 + Excel

按日期范围扫描邮箱，先过四层筛选；附件直接进入识别，只有下载链接的发票走恢复流程。识别后按规则分类、命名并归档，无法确认的进入待复核。

交付物
分类目录 / 结果明细.xlsx / 待人工复核 / 运行证据
适合每月集中报销：一次扫描覆盖多个平台与多种票据。

只收集，不解释：把附件交给自己的工具链

  • 01连接邮箱
  • 02保存附件
  • 03写 manifest.jsonl

只把邮箱里的发票附件保存到 inbox/，并为每个附件记录 SHA-256、相对路径、邮箱、UID、主题、发件人、收到时间。不识别、不改名、不归档、不写台账。

交接契约
inbox/ + manifest.jsonl
适合已经有自己的归档/识别工具，或想把「收集」与「整理」拆成两步的用户。

不连邮箱也能用：离线整理任意文件夹

  • 01选择文件夹
  • 02扫描
  • 03离线识别
  • 04分类副本
  • 05原件保留

扫描手机导出、微信/支付宝下载目录或拍照发票文件夹，离线识别后按规则分类。默认在所选文件夹内原地整理：分类文件放子目录，原件按原文件名、原内容、原相对路径保留在 整理前发票/；重复件进 duplicates/。

目录变化
分类/ + 整理前发票/ + duplicates/ + 结果明细.xlsx
不需要邮箱和网络；再次整理幂等，已整理文件不会被重复归档。

本地识别

确定性优先，OCR 兜底

选择一份材料，看看它会走哪条识别通道。识别全程不联网、不需要 API Key，也不调用模型服务。

文本层 ≥ 40 字符 → 文本解析 OCR：前 2 页 · 200 DPI 图片：JPG / PNG / WEBP / BMP / TIFF OFD：zip + ofd:TextCode < 1000 字节 → invalid 无法确认 → 待人工复核
离线一致性校验：合计金额 + 税额应与价税合计勾稽，日期可解析，票号是合法数字串；无法确认时不猜测，转入「待人工复核」由用户核对。

链接发票

三级恢复：从「点击下载」到本地 PDF

系统先按链接域名与路径识别平台，再选择最优恢复策略；恢复在独立子进程中执行，超时可整棵进程树终止。

TIER 01

百望云自动化

识别百望云家族链接，先探测预览 API / 直连产物，再用 Playwright 打开页面捕获下载。

  • 登录态与下载动作自动化
  • 下载后按期望字段比对
  • 正式 PDF / XML 存档
TIER 02

平台直连

识别税务、诺诺、航信、票易通、京东云、拼多多等 7 类直连族，优先走有界 HTTP 请求。

  • 发票族群识别
  • 有界请求 + 重试
  • 本地字段校验
TIER 03

网页转 PDF

未知但可信的发票网页：打开页面，检测登录/验证码/产品页，按 A4 渲染成 PDF。

  • 平台产品页安全跳过
  • 渲染前检查发票证据
  • 无证据不接收

子进程隔离

恢复任务在独立进程中运行，超时按进程树终止，避免拖死主程序。

并发受限

整体并发有上限，强供应商限流且同组串行，降低触发风控的概率。

字段闭环

下载结果必须匹配邮件正文提取的票号或「销方 + 金额 + 日期」，否则拒收。

筛选与准入

四层邮件筛选 + 三级附件决策

不是每封邮件都进入识别。先判断邮件像不像发票，再判断附件值不值得处理，最后才进入识别与校验。

L1 域名白名单：命中差旅相关域名的邮件优先进入候选；非白名单邮件仍可凭主题、正文或二维码信号进入，但优先级更低。
A 层 · 丢弃跳过

追踪像素、Logo、装饰图、极小尺寸/极小字节附件、营销素材。

B 层 · 暂存保留

附件 >5MB、ZIP 解包失败或超限、低置信度候选：保留但不进入识别。

C 层 · 进入识别处理

正常 PDF / OFD / XML / 图片附件，进入本地识别与校验。

ZIP 解包限制：最多 64 个成员、单成员 16MB、总量 32MB、嵌套 2 层；超限只记录不展开。附件尺寸与像素阈值用于拦住追踪像素和装饰图。

费用归类

规则可配置，归档文件夹自动生成

费用类目不写死在代码里。内置默认、全局规则、当前发票库规则逐层覆盖；一条规则只需要「目标票种 + 关键词 + 金额范围」。

隐私与安全

数据留在本机，边界写进代码

安全不是一句「本地处理」，而是只读邮箱、加密凭据、路径白名单、URL 公网校验与前端 CSP 的组合。

邮箱只读

IMAP 只读取，不发送、不删除、不修改邮件。

识别不上传

解析、OCR、归档均在本机完成，不调用模型服务。

凭据加密

Windows DPAPI / macOS Keychain，设置文件不存明文。

URL 安全

只允许公网单播地址，DNS 钉扎与响应端复验，日志脱敏。

路径白名单

桥接只允许访问用户确认过的目录，拒绝 UNC 与路径穿越。

前端 CSP

桌面页面默认 default-src 'none'，脚本与资源仅本地来源。

无法可靠确认的票据不会被硬归类：进入「待人工复核」是正常路径，不是程序故障。

桌面端最适合日常使用；命令行适合脚本化与批量；DSH 插件适合把整理工作放进 AI 工作流侧边栏。

四步完成一次整理

  • 1. 选择任务模式与输出目录。
  • 2. 填写邮箱地址与 IMAP 授权码，可先测试连接。
  • 3. 选择日期范围（首次建议覆盖 180 天以上），开始处理。
  • 4. 在结果分析页查看汇总、处理待复核项并导出 Excel。

首次配置提示

QQ / 163 / 88 的授权码不是登录密码；修改邮箱密码后授权码可能失效。识别引擎已内置，无需填写 API Key。图片与扫描件由本地 OCR 处理。

# 预览本地文件夹整理（默认 dry-run、原地输出）
python organize_cli.py organize "D:\发票\待整理"

# 真正执行整理
python organize_cli.py organize "D:\发票\待整理" --apply

# 指定独立归档库（原件保留在原文件夹）
python organize_cli.py organize "D:\发票\待整理" --output "D:\发票库" --apply

# 只提取邮箱附件到 inbox（授权码支持 env:变量名）
python organize_cli.py fetch --email you@qq.com --auth-code env:QQ_AUTH_CODE --output "D:\发票库"

# 规则维护与解释
python organize_cli.py rules test --text "酒店住宿" --amount 150.00
python organize_cli.py rules explain --library "D:\发票库" --text "酒店"

边界与取舍

它擅长什么，不承诺什么

本地离线识别换来了隐私与零 API 成本，也带来明确的能力边界；正确使用方式是「自动整理 + 人工复核」。

⚖️
识别是辅助，不是结论

不保证票面数据或归档结果 100% 正确；报销、入账、税务判断必须人工复核。

📮
只支持三种邮箱

QQ、163、88；其他邮箱需要扩展通道注册表。

🧐
待复核是正常路径

图片模糊、非标准票据、加密 PDF、金额勾稽异常都会进入待人工复核。

📁
本地整理默认原地

会改变文件夹结构；建议先在副本上试运行（CLI 支持 --dry-run），重要目录先备份。

🔁
规则修改不回迁旧文件

新归档进入新文件夹，旧文件不会自动搬家。

🧾
不含联网验真 / 报税

不提供发票真伪查验、税务申报或财务系统对接。

📊
Excel 文件名以实际为准

README 中写作 summary_report.xlsx，当前实现为 结果明细_<时间戳>.xlsx。

🍎
macOS 版本未签名

首次打开需要在系统设置中放行。

常见问题
Q识别需要联网或填写 API Key 吗？›
不需要。文本层 PDF、OFD、XML 直接解析，扫描件与图片由内置本地 OCR 识别；模型随依赖提供，识别过程不联网、不调用模型服务。
Q为什么有发票进入「待人工复核」？›
当本地解析与规则校验无法可靠确认时（图片模糊、非标准票据、加密 PDF、金额勾稽不平、未命中归类规则等），系统会放入待人工复核目录，由用户确认，而不是硬猜。
Q支持哪些邮箱？授权码是什么？›
支持 QQ、163、88。授权码是邮箱后台生成的第三方客户端专用密码，不是登录密码；QQ 修改密码后授权码可能失效，需要重新生成。
Q本地文件夹整理会移动或删除原文件吗？›
默认原地整理时，原件按原文件名、原内容、原相对路径保留在「整理前发票/」，不删除；分类结果以副本形式放入分类目录。重复件移入 duplicates/。
Q修改归类规则后，旧文件会自动搬家吗？›
不会。规则修改只影响之后的新归档；已有文件保持原位置。
Q为什么第一次扫描发票很少？›
部分邮箱默认只拉取近 30 天邮件。把起始日期调整到 180 天以上，并在邮箱 IMAP 设置里选择收取全部邮件。
QExcel 文件叫什么名字？›
当前实现导出「结果明细_YYYYmmdd_HHMMSS.xlsx」，包含分类汇总、成功明细、异常记录三个工作表。README 中的 summary_report.xlsx 是旧称。
